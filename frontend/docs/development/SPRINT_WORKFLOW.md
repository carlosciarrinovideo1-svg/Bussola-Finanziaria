# Sprint Workflow

## Sequenza obbligatoria

1. Analisi minima necessaria.
2. Modifica mirata.
3. Build.
4. Verifica.
5. Commit.
6. Push.
7. Aggiornamento documentazione.

## Regole

Uno sprint:
- un obiettivo;
- modifiche limitate;
- risultato verificabile.

Non introdurre nuove architetture senza necessità.
Non duplicare componenti o servizi esistenti.
